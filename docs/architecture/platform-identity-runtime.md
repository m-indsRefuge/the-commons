# Platform + Identity Runtime

This document describes the executable Stage 1 identity path established by the foundation branch.

## Runtime flow

1. Better Auth authenticates a human through GitHub OAuth.
2. GitHub OAuth is explicitly limited to `read:user` and `user:email`.
3. Successful authentication creates or loads Better Auth's authentication identity and session.
4. Authentication alone does not grant Commons membership.
5. An authenticated user redeems a valid Commons invite.
6. Invite redemption runs inside a PostgreSQL transaction:
   - validate token hash;
   - validate expiry, revocation, consumption, and email binding;
   - reject an existing membership;
   - create ACTIVE membership;
   - atomically consume the invite;
   - append the activation audit event.
7. Member authorization resolves the Better Auth user ID to a Commons membership before applying policy.

## Trust boundaries

- Better Auth owns authentication identity, OAuth accounts, and sessions.
- The Commons owns invites, membership, roles, suspension, audit events, and object authorization.
- GitHub repository permissions are absent from this subsystem and will use a separate GitHub App.
- Raw invite tokens are returned only at creation time and are persisted only as HMAC-SHA256 hashes.
- Runtime secrets are validated lazily at request or database use, keeping production builds independent of developer secrets.

## Routes

- `/api/auth/[...all]`: Better Auth handler.
- `POST /api/admin/invites`: active ADMIN only; creates an invite and returns the one-time raw token.
- `POST /api/onboarding/redeem`: authenticated GitHub identity; redeems a Commons invite.
- `GET /api/me`: reports authentication and Commons membership state.

## Migration contract

The Drizzle TypeScript schema is the source of migration generation.

```text
npm run db:generate
npm run db:check
```

Review generated SQL before applying it. Application startup never applies migrations.

When Better Auth is upgraded, compare the auth schema against the schema generated by the matching Better Auth CLI version before generating a database migration.
